# 换脸产品：从技术到生意的全图

这份文档回答三个问题：**技术怎么选、玩法怎么设计、怎么不踩法律红线。**

---

## 一、技术路线：四种做法，成本差 100 倍

| 方案 | 代表实现 | 效果 | 显存/算力 | 适合谁 |
|---|---|---|---|---|
| A. 人脸融合 | 早期「变脸秀」类 App | ★☆☆☆☆ 只是把两张脸按 alpha 叠加 | 无 | 只想做个滤镜玩具 |
| B. 几何换脸 | 本项目 `classic` 引擎 | ★★☆☆☆ 对齐 + 融合，表情不迁移 | 无 | 验证产品链路、原型 Demo |
| C. 换脸模型（**主流**） | InsightFace + inswapper_128 | ★★★★☆ 表情姿态都能迁移，128×128 生成后贴回 | 模型 500MB，CPU 可用 | 绝大多数图片类产品 |
| D. 扩散模型 | InstantID / IP-Adapter / PuLID / Flux + ControlNet | ★★★★★ 能换风格、改年龄、换妆造，不只是换脸 | 6~24GB 显存 | 想做「AI 写真」「AI 形象照」 |

**推荐路线：C 起步，D 做增值。**

- 先用 C 把 MVP 跑通（成本最低，一张 CPU 机器就能服务）
- 用户量起来后，把 D 作为付费高级功能（生成慢但惊艳，天然适合计费）

### C 方案的工程细节（值得先搞清楚）

```
源图 → 检测 → ArcFace 提 512 维特征
                    ↓
目标图 → 检测 → 对目标脸做 128×128 对齐裁剪 → inswapper 生成新脸 → 贴回原图
                                                              ↓
                                          GFPGAN / CodeFormer 修复细节（可选，但强烈建议）
```

- `inswapper_128.onnx` 只有 500MB 左右，但它只输出 128×128 的脸，
  **不修复就会一眼假**。所以生产管线里 GFGAN/CodeFormer 这一环几乎不能省。
- 贴回时如果目标是侧脸、被遮挡（手、头发、眼镜），需要额外做遮挡感知的蒙版，
  否则会出现「脸浮在头发上面」的廉价感。
- 想支持视频：逐帧跑 + 光流做时序平滑 + 音频直接搬运。抖动和闪烁是视频换脸
  最难的部分，不是单帧质量。

## 二、玩法灵感：换脸本身不是产品，场景才是

「换脸」只是一个能力。**孤立地卖换脸，用户玩两次就走了；绑定一个具体场景，才有留存。**

### 1. 娱乐社交类（最容易起量）

- **AI 剧组**：上传一张脸，一键生成「如果我演《甄嬛传》」的九宫格剧照
- **年代照相馆**：一张自拍穿越民国 / 80 年代 / 赛博朋克
- **情侣 / 亲子合影**：异地情侣合成合照；把去世的亲人合进全家福（情感浓度极高）
- **宠物拟人**：把主人的脸换到自家猫狗身上做表情包
- **毕业照 / 合影恶搞**：多人图批量换脸（本项目已实现 `/api/swap/batch`）

### 2. 生产力类（客单价高、留存好）

- **电商模特图**：同一件衣服批量生成不同面孔的模特图，省掉拍摄成本
- **口播视频本地化**：一个主播的脸 × 多语言版本，做跨境投放
- **企业培训 / 数字员工**：统一形象的口播内容批量生产
- **影视预演**：开机前用换脸做选角预览（行业里已经在用）

### 3. 工具增值类（做深度而不是做广度）

- **换脸 + 写真**：结合 LoRA 训练专属人像模型，出图更像本人（客单价 30~200 元）
- **换脸 + 一键成片**：换完直接套模板出短视频，省掉剪辑
- **API 服务**：把换脸做成接口，卖给上面两类的开发者

### 值得抄的产品设计细节

- **前后对比滑块**（本项目已做）：让用户自己「发现」效果，比任何文案都有说服力
- **微调参数**：强度、羽化、肤色匹配全部开放，用户会为了调出满意效果而反复使用
- **首图免费、高清/去水印收费**：转化率最高的付费点
- **成品直接生成分享图**：带平台水印的分享是零成本获客

## 三、合规：这是这个赛道唯一的生死线

> **技术风险可以迭代，法律风险一次就够死。**

### 必须做的四件事

1. **肖像权授权**
   任何上传他人照片的场景，都要有明确的「我确认已获得本人授权」勾选项，
   并留存记录。未经同意换脸并在公开场合传播，在《民法典》第 1019 条下
   属于侵犯肖像权；若内容涉及侮辱、贬损，还可能触及名誉权甚至刑事风险。

2. **不可去除的水印 + 内容标记**
   国内《互联网信息服务深度合成管理规定》要求深度合成内容**显著标识**；
   海外欧盟 AI Act、《Take It Down Act》等也在陆续落地。
   技术上可以做 C2PA 元数据签名，或在画面角落烧入水印。

3. **禁止清单 + 前置拦截**
   这些场景必须硬性禁止，且要在**生成前**拦截而不是事后删除：
   - 涉及未成年人的任何性化内容（绝对红线，无例外）
   - 未经同意的性化内容（色情换脸，多数国家已入刑）
   - 政治人物、公众人物的虚假言论视频
   - 冒充身份进行诈骗、开户、验证

4. **数据最小化**
   人脸是敏感个人信息（生物识别信息），受《个人信息保护法》严格规制。
   上传的图**默认不长期存储**，用完即删，并在隐私政策里写清楚；
   人脸特征向量比原图更敏感，不要随手落库。

### 从设计上就防住的做法

- **在线换脸不做离线下载**：降低被二次滥用的风险
- **只允许换「已授权的脸」**：让用户先做一次真人核验，建立「已授权脸库」，
  之后只能从库中选脸去换别人——这类产品形态在合规上稳得多
- **举报 + 快速下架通道**：法规要求的标配
- **年龄门 + 内容审核模型**：上传图先过一次 NSFW / 未成年人检测

## 四、如果要继续往下做，下一步做什么

按投入产出排序，给你一条清晰的升级路径：

1. **换 insightface 引擎**（半天）→ 效果立刻从「一眼假」变成「能发朋友圈」
2. **加 CodeFormer 修复**（半天）→ 消除 128 分辨率的模糊感
3. **接 SQLite 做持久化 + 用户体系**（1 天）→ 能记录历史、能计费
4. **加视频支持**（3~5 天）→ 逐帧换脸 + 光流平滑
5. **加内容审核 + 水印 + 授权勾选**（1 天）→ 具备上线的最低合规条件
6. **换 SCRFD 检测器 + 遮挡感知蒙版**（2 天）→ 处理侧脸和遮挡，质感再上一档

## 五、一句话总结

换脸的技术门槛已经很低了 —— 难的是**找到愿意反复用的场景**，
和**在合规上不出事**。前者靠产品设计，后者靠一开始就把约束写进架构里，
而不是等做大了再补。
